# Data snapshots and fallbacks

These files are **local snapshots and offline fallbacks**, not the only data
source. `DatasetService` checks their age on startup and refreshes the subzone
and HDB datasets from data.gov.sg when they are older than 24 hours. Live
environment readings come from the data.gov.sg real-time APIs.

`bootstrap.buildContext()` looks for these files in `backend/assets/data/`:

```text
subzones.geojson
planning_area_to_hdb_town.json
amenities.json
tertiary_schools.json
environment_baselines.json
hdb_resale.csv
commute_matrix.json
```

The small files in `backend/tests/fixtures/` show the expected shapes. The
following real assets are already populated:

- `subzones.geojson` (URA 332 subzones)
- `hdb_resale.csv` (HDB resale transactions)
- `planning_area_to_hdb_town.json`
- `environment_baselines.json`
- `commute_matrix.json`
- `amenities.json` (1,172 base points; see below)
- `tertiary_schools.json` (28 JC/university points merged at load time)

If `amenities.json` is absent or unreadable, factsheets return an empty amenity
list with a `MISSING_SOURCE_DATA` warning and the school/amenity criteria are
excluded from scoring and weights renormalised.

## `subzones.geojson`

Use the URA **Master Plan 2019 Subzone Boundary (No Sea) (GEOJSON)** dataset:
`d_8594ae9ff96d0c708bc2af633048edfb` on data.gov.sg.

The loader accepts `SUBZONE_C`, `SUBZONE_N`, `PLN_AREA_N` and `REGION_N`
properties. A `townName` or `TOWN` property is optional when
`planning_area_to_hdb_town.json` is populated.

## `planning_area_to_hdb_town.json`

Maps URA planning areas to HDB town names, for example:

```json
{
  "TAMPINES": "TAMPINES",
  "BEDOK": "BEDOK",
  "KALLANG": "KALLANG/WHAMPOA"
}
```

Planning areas without an HDB town should be omitted or mapped to `null`. The
shipped file is populated with the mapping used by the application; update it
from HDB's town definitions if the source data changes.

## `hdb_resale.csv`

Use the HDB **Resale flat prices based on registration date from Jan-2017
onwards** dataset: `d_8b84c4ee58e3cfc0ece0d773c8ca6abc`.

Required columns:

```text
month,town,flat_type,resale_price,floor_area_sqm
```

Pricing always uses the HDB town median and every row is labelled
`isTownProxy=true`. A `subzone_code` column is not required and is not used for
pricing; the project decision is to keep the town-level proxy rather than build
a block-to-subzone mapping.

## `amenities.json`

Generated by `scripts/build_amenities.py` (or `make amenities`). The file
contains provenance metadata plus a list of amenity points:

```json
{
  "metadata": {
    "generatedAt": "2026-10-21T13:25:17+00:00",
    "method": "buffer_distance_density",
    "radiiKm": {
      "schools": 1.0,
      "tertiarySchools": 1.0,
      "mrt": 0.8,
      "parks": 0.5,
      "healthcare": 2.0,
      "malls": 1.0
    }
  },
  "items": [
    {
      "name": "Tampines Primary School",
      "category": "Primary School",
      "latitude": 1.351,
      "longitude": 103.941
    }
  ]
}
```

Supported categories are `Primary School`, `Secondary School`, `Tertiary School`,
`Polyclinic`, `Hospital`, `Park`, `Shopping Mall` and `MRT`. The pipeline uses:

| Category | Source |
| --- | --- |
| Primary/secondary schools | MOE **General information of schools** (data.gov.sg), postal codes geocoded with OneMap Search |
| Tertiary schools | `tertiary_schools.json` supplement: JCs, Millennia Institute, mixed-level JC/IB schools and autonomous universities |
| Parks | NParks **Parks and Nature Reserves** (data.gov.sg); each polygon is represented by a `representative_point()` |
| MRT | LTA **MRT Station Exit** (data.gov.sg); exits are grouped into one point per station |
| Polyclinics | HPB **Breast Screening Centre** + MOH **Vaccination Polyclinics** (data.gov.sg) |
| Hospitals | OneMap **Hospitals** theme (`moh_hospitals`, MOH) |
| Shopping malls | OneMap Search for `mall` / `shopping centre`, supplemented by LTA **Carpark Rates** major-mall names and a short named-mall list |

**Count method:** buffer-distance density, not point-in-polygon. The backend
takes each subzone's representative point and counts every amenity point within
the fixed radius. The radii are 1.0 km for primary/secondary/tertiary schools and
malls, 800 m for MRT, 500 m for parks, and 2.0 km for polyclinics and hospitals.
The factsheet list shows all amenities within 2 km, sorted by distance.

`tertiary_schools.json` is merged into the amenity list at load time, so the
28 tertiary points count toward the hard minimum filters and appear on the map
without regenerating `amenities.json`. `scripts/build_amenities.py` also reads
the supplement when rebuilding the snapshot.

`POST /api/v1/data/refresh` reuses the local `amenities.json` point layer as the
cached raw POI source, recomputes all subzone aggregates in memory, and writes
the updated snapshot back to `amenities.json`. No network call is required for
the amenity rebuild. The refreshed file also contains an `aggregates` object
keyed by subzone code with the computed counts and nearest distances.

## `environment_baselines.json`

Static values used for scoring, keyed by subzone code:

```json
{
  "TAMPINES01": {
    "greenCoveragePercent": 35.5,
    "weatherPattern": "Partly Cloudy",
    "pm25Baseline": 12.0,
    "granularity": "REGION",
    "asOf": "2025-12-01T00:00:00+08:00"
  }
}
```

Live PM2.5, UVI and forecast values are fetched separately by
`LiveEnvironmentProvider` and are display-only; they do not affect scores.

## `commute_matrix.json`

Precomputed CBD commute estimates:

```json
{
  "subzones": {
    "TAMPINES01": {
      "CBD": {
        "durationMinutes": 35,
        "distanceKm": 14.2,
        "transferCount": 1
      }
    }
  }
}
```

The shipped matrix covers 319/332 subzones. The 13 missing entries are recorded
in `metadata.errors`, marked unavailable, and excluded from ranking/factsheet
selection. Custom workplaces use live OneMap routing for a top-50 shortlist; the
remainder receive straight-line PT estimates so every ranked candidate has a
commute value.
